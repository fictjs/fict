# fict

## 0.31.0

### Breaking Changes

- Remove the legacy TypeScript/Babel compiler stack and make the Rust native compiler mandatory.
  - `@fictjs/compiler` now exposes only the Rust request API; `./legacy` and `createFictPlugin` are removed.
  - `@fictjs/vite-plugin` no longer accepts legacy or shadow backend selection and always uses the native compiler.
  - `@fictjs/webpack-plugin` no longer provides the Babel preset/legacy loader path and requires the native compiler.
  - `@fictjs/babel-preset` is retired; `0.30.1` remains the final legacy-compatible release and rollback target.

  Follow `docs/migration-guide.md` before upgrading. Native compiler installation failures now fail closed instead of falling back to Babel.

## 0.28.0

### Breaking Changes

- **Preview resumability:** replace imports from `fict/loader` with
  `fict/experimental/loader`. The former subpath is no longer exported, and the
  new entrypoint remains experimental with no Core 1.0 semver guarantee.
- `$store` now deep-proxies only arrays and plain records. Class instances and
  branded platform objects such as `Date`, `Map`, and `URL` remain opaque so
  private fields and internal slots keep their native receiver. Keep reactive
  mutable fields in plain objects or arrays when deep tracking is required.

### Minor Changes

- Make `$store` reflection reactive without invoking getters. The `in`
  operator now distinguishes a missing key from an own key whose value is
  `undefined`, and descriptor subscribers update correctly after definitions,
  deletions, and array truncation.
- Clear `resource(...).read(...).data` reactively when the current fetch or
  refresh fails instead of exposing the previous successful value as current
  data after an error.
- Fix the re-exported `createSelector` for custom equality functions and shared
  observers so every equivalent key updates and disposing one root does not
  detach subscribers owned by another root.

## 0.27.0

### Breaking Changes

- **Preview — resumable SSR snapshots:** the matching SSR writer now emits
  snapshot schema v2. `fict/loader` rejects missing-version and v1 snapshots
  by default because historical v1 writers used two byte-compatible but
  semantically different props encodings.
  - Deploy the SSR writer, cached HTML/PPR output, client loader, manifest, QRL
    chunks, and external stream runtime as one build, and purge documents
    generated by older writers.
  - For intentionally retained legacy output, explicitly select
    `createLegacySnapshotMigration('raw-props')` for unversioned/v1 writers
    through v0.21 or `createLegacySnapshotMigration('encoded-props')` for v1
    writers from v0.22 through v0.26. Select from deployment history, never
    payload shape.
  - Use `onSnapshotRejected` to mount an application-owned CSR fallback after
    the loader disengages; `onSnapshotIssue` is telemetry-only.

### Minor Changes

- Isolate resource caches per SSR request and make custom cache keys include
  their prefetch arguments, preventing cross-request and same-key collisions.
- Expire zero-TTL resources immediately, enforce cache bounds after fetches,
  and normalize synchronous or asynchronous fetch failures.
- Normalize lazy-loader failures, cache falsy rejection reasons, and restart
  suspended loads when a lazy boundary is reset.
- Publish the public package with runtime 0.27 so applications receive the
  loader, lifecycle, ownership, namespace, and deferred-rendering fixes
  described in the runtime changelog.
