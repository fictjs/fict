### Breaking Changes

**Preview — resumable SSR snapshots:** Fict now writes snapshot schema v2.
`fict/loader` and `@fictjs/runtime/loader` reject unversioned and v1 snapshots
by default because historical v1 writers used two byte-compatible but
semantically different props encodings.

Deploy the SSR writer, cached HTML/PPR output, client loader, manifest, and QRL
chunks as one build and purge documents generated by older writers. Deployments
that must consume known legacy output must explicitly configure
`createLegacySnapshotMigration('raw-props')` for unversioned/v1 writers through
v0.21, or `createLegacySnapshotMigration('encoded-props')` for v1 writers from
v0.22 through v0.26. Select the migration from deployment metadata, never from
payload shape. Applications can use `onSnapshotRejected` to mount their own CSR
fallback after the resumable loader disengages.

The compiler and official Babel/Vite integrations now lower TypeScript before
Fict analysis, accept TypeScript enums, namespaces, and supported declare
fields, compile macros in normal `.ts` and `.js` modules, prepare imported hook
metadata before clean-build transforms, honor configured glob filters, and keep
library metadata scoped to the correct facade. This also preserves custom-event
casing and bindings through implicit table colgroups.

Runtime and `fict` now harden per-document resumable-loader isolation, malformed
and partial snapshots, serialized symbol references, lifecycle/error-boundary
cleanup, delegated event targets, lazy loader retries, and resource cache
isolation, expiry, keying, and bounds. Child, conditional, portal, Suspense, and
ErrorBoundary materialization no longer inherits a parent effect's dependencies,
preventing production self-notification loops while preserving explicit getter
and branch tracking. Namespace-aware DOM writes also retain their qualified
`xlink:`/`xml:` prefixes in browser and SSR output.

Compiler, Babel preset, and Vite plugin CommonJS consumers now resolve
condition-specific `.d.cts` declarations. The ESLint plugin has no lint-rule
behavior change; it is included to keep the fixed Core release train in
lockstep.
